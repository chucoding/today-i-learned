# GIT 충돌전략

GIT 브랜치 충돌 발생 시 대처 전략

## 충돌 종류
- 기존 PR 브랜치가 있고 그 PR의 충돌을 푸는 경우
  - 작업 중인 PR 브랜치에 PR 대상 브랜치의 최신 변경을 merge하거나 rebase해서 PR을 mergeable 상태로 만듬
- 단방향 동기화용 PR
  - source 브랜치에서 충돌 해결용 브랜치를 만들고, target 브랜치를 merge한 뒤, source 브랜치 대상으로 PR을 생성
  - source는 qa->stage가 될 수도 있고 main->develop이 될 수도 있음.


## Git Rebase

feature 브랜치를 최신 `develop` 기준으로 정리할 때는 rebase로 깔끔하게 병합할 수 있다.

### 설명

한 브랜치의 베이스 커밋을 다른 브랜치의 최신 커밋으로 재설정하여, 커밋 히스토리를 일직선으로 정리하는 명령

### 사용방법

1. 최신 브랜치 정보 받아오기

```shell
git fetch origin
```

2. 작업 중인 브랜치에서 리베이스 수행

```shell
git rebase origin/develop
```

3. 충돌 수정 후

```shell
git rebase --continue
```

4. 원격 feature 브랜치에 반영

```shell
git push --force-with-lease
```


```
변경을 받아야 하는 브랜치에서 충돌 해결용 브랜치 생성
→ 그 브랜치에 반영하려는 브랜치를 merge
→ 충돌 해결
→ 변경을 받아야 하는 브랜치 대상으로 PR 생성
```

이 방식은 PR의 base가 변경을 받아야 하는 브랜치가 되므로, “이 브랜치에 저 브랜치의 변경을 반영한다”는 의도를 가장 명확하게 보여준다.

## qa -> stage 충돌

`qa` 변경을 `stage`에 반영해야 하지만 `qa`, `stage`에 직접 push할 수 없고, `stage` 기능이 `qa`로 역류하면 안 되는 경우에 사용한다.

```shell
git checkout stage
git pull origin stage
git checkout -b fix/qa-to-stage-conflict

git fetch origin
git merge origin/qa
# 충돌 해결
git commit
git push origin fix/qa-to-stage-conflict
# base: stage, compare: fix/qa-to-stage-conflict 로 PR
```

## main -> develop 충돌

hotfix 등이 반영된 `main` 코드를 `develop`에 동기화해야 하는 경우에 사용한다.

```shell
git checkout develop
git pull origin develop
git checkout -b fix/main-to-develop-conflict

git fetch origin
git merge origin/main
# 충돌 해결
git commit
git push origin fix/main-to-develop-conflict
```
