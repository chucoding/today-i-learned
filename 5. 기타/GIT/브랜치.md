# branch

## merge

### merge commit(fast-foward merge)

모든 Commit History를 남기는 Merge

### squash and merge

현재 브랜치의 모든 Commit History를 상위브랜치에서 하나의 새로운 Commit으로 합치는 방식(EX. PR 제목이 develop브랜치 Commit 메시지가 됨.)

## 명령어

### checkout

```powershell
# 브랜치 생성과 동시에 checkout
git checkout -b feature/login develop     # feature/기능요약
git checkout -b feature/136-login develop # feature/{issue-number}-{feature-name}

# 브랜치 이동
git checkout <브랜치 명>
```

### delete

```powershell
git branch -d <브랜치 명>
```

### push

```powershell
git push
```

> 💡 원격(GitHub)에서 삭제된 브랜치를 로컬에서 다시 올리기  
>
> - 로컬 브랜치 올리기
>   - `git push -u origin <브랜치 명>`
>   - u 옵션을 사용해서 매번 push 할때마다 경고 발생하는 부분 제거

### 로컬 브랜치 정리

1. 싱크 맞추기
  ```shell
  git fetch --prune
  ```
2. 원격에서 삭제된 브랜치 조회
  ```shell
  git branch -vv | grep ': gone]'
  ```
3. 대량 삭제(사용주의)
  ```shell
  git branch -vv | awk '/: gone]/{print ($1=="*" ? $2 : $1)}' | xargs git branch -d
  ```
  > 스쿼시머지하는 경우에는 커밋 ID가 새로 생성되는거기 때문에 `not fully merged`가 나타남. 이 경우에는 `-D` 옵션으로 제거해야됨.

**release 브랜치 네이밍 규칙**

1. release-RB_...
2. release-..
3. release/...

ex )
release-1.2.2

**hotfix 브랜치 네이밍 규칙**

1. hotfix-1.2.3 
(앞선 release 버전보다 버전업이 되어야함
이유는 hotfix 브랜치는 "배포된 버전"을 가지고 수정하는 경우이기때문에
배포된 버전보다 1발짝 업그레이드 된 버전으로 commit message를 적어줘야함)

```markdown
git reset --soft HEAD^
```
