## 정의

- 에이전트가 참고할 지식(도메인, 근거, 규칙)을 저장소 문서로 쌓아 둔 위키.
- 에이전트가 필요할 때 검색(MCP 등)으로 꺼내 읽음.
- 사람이 읽는 위키와 달리 라우팅 문서(`index.md`)와 메타데이터(키워드, 별칭)로 검색에 걸리게 관리함.

> [!NOTE]
> **Skill과의 차이점**
>
>
> |         | LLM Wiki        | Skill                                     |
> | ------- | --------------- | ----------------------------------------- |
> | 닿는 방식   | 에이전트가 판단해 당겨 읽음 | `description`이 상주하다 작업 순간 자동 로드           |
> | 담는 것    | 근거와 기준(왜)       | 실행 지침(어떻게)                                |
> | 컨텍스트 비용 | 호출 전 0          | 설명은 상주, 본문은 호출 시                          |
> | 범위      | 호출할 때만 읽힘       | 사용자 전역에 두면 무관한 프로젝트에도 로드됨. 프로젝트 범위로 한정 필요 |
>
>
> - 함께 쓰는 법 : 스킬은 얇게(트리거 + 체크리스트 + 위키 포인터), 상세는 위키에.

## git history와의 차이

- git history와 PR은 변경 이벤트 로그, 위키는 그 로그를 현재 상태로 정리해 둔 결과.
  - DB로 치면 이벤트 소싱 로그와 materialized view의 관계.

| | git history, PR | LLM Wiki |
|---|---|---|
| 답하는 질문 | 이 코드가 왜 이렇게 바뀌었나 | 지금 이 작업에 무엇을 알아야 하나 |
| 단위 | 커밋, diff, 리뷰 코멘트에 흩어짐 | 주제별 문서 하나 |
| 찾는 방법 | 키워드 매칭(`git log --grep`, `gh search`) | `index.md` 라우팅으로 읽을 문서만 지정 |
| 범위 | 저장소 하나 | 여러 저장소를 주제로 묶음 |
| 낡은 결정 | 뒤집힌 결정도 그대로 섞여 있음 | 현재 정본만 남기고 상태(초안, 정본) 표시 |
| 탐색 비용 | 검색 호출 여러 번과 큰 diff로 컨텍스트 소모 | 포인터를 따라 필요한 문서 몇 개만 읽음 |
| 유지 비용 | 작업하면 자동으로 쌓여 추가 비용 없음 | 원자료와 어긋나지 않게 따로 갱신하고 검증해야 함 |

- git에 남지 않는 지식이 위키의 몫
  - 커밋으로 이어지지 않은 조사 결과와 버린 대안
  - "이건 근거로 쓰지 않는다" 같은 부정 지식과 함정
- 탐색 비용을 유지 비용으로 바꾸는 선택. 문서마다 티켓과 PR 링크를 걸어 근거는 git에, 요약과 라우팅은 위키에 둠.
