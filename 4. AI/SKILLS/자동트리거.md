# 자동 트리거
클로드 코드가 스킬을 스스로 찾아 쓰는 방식. 지시문을 따로 넣지 않아도 동작함.

## 스킬을 찾는 위치
세션이 시작될 때 아래 경로를 훑어서 목록을 만든다.

```
~/.claude/skills/<이름>/SKILL.md          개인 스킬 (모든 프로젝트에서 사용)
<프로젝트>/.claude/skills/<이름>/SKILL.md   프로젝트 스킬
```

플러그인 스킬은 `플러그인명:스킬명` 형태로 올라온다.

## 로딩 순서
본문 전체를 항상 들고 있지 않는다. 필요할 때만 읽는다.

```
세션 시작   ->  frontmatter의 name + description 만 목록으로 로드
대화가 description과 맞음
             ->  모델이 Skill 도구 호출
             ->  이때 SKILL.md 본문 전체 로드
```

컨텍스트를 아끼는 구조라 스킬을 많이 등록해도 부담이 적다.

## description이 트리거 조건
```yaml
---
name: pdf-extract
description: PDF에서 표와 텍스트를 추출한다. 사용자가 PDF 파일을 주거나 문서에서 데이터를 뽑아 달라고 할 때 사용한다.
---
```

`name`과 `description` 두 개가 필수다.

description은 요약이 아니라 **언제 쓰는지**를 적는 자리다. 본문이 아무리 정확해도 여기가 부실하면 트리거되지 않는다. 사용자가 실제로 칠 법한 표현을 넣는 게 핵심.

## 심링크로 등록
스킬 정본이 다른 저장소에 있으면 복사하지 않고 심링크를 건다.

```bash
ln -s <정본저장소>/skills/pdf-extract ~/.claude/skills/pdf-extract
```

정본을 고치면 배포 없이 즉시 반영된다. 팀에서 스킬을 공유할 때 사본이 갈라지는 걸 막을 수 있다.

## 주의
description 매칭은 모델의 판단이라 정규식처럼 결정론적이지 않다.

- 지시문 파일(AGENTS.md 등) : 항상 로드되는 지시
- 스킬 description : 매칭되면 뜨는 후보

보장 강도는 한 단계 낮다. 트리거가 안 뜬다고 지시문을 늘리기보다 **description을 실제 입력 문구에 가깝게 손보는 쪽**이 낫다. 고칠 곳이 한 군데로 유지된다.
