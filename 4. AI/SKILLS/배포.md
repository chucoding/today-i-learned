## 배경

정본 저장소의 스킬을 각자 PC에 복사해 쓰면, 복사한 날 이후의 변경이 들어오지 않음.

## 배포 방식 비교


| 방식                                | 최신 유지 조건          | 팀원 준비물              | 맞는 상황                |
| --------------------------------- | ----------------- | ------------------- | -------------------- |
| 1. 각 저장소 `.claude/skills/`        | `git pull`        | 없음                  | 그 저장소에서만 쓰는 스킬       |
| 2. 글로벌 `.claude/skills/` + 심볼릭 링크 | 매번 `git pull` 필요. | `git clone` + 링크 생성 | 혼자 쓰는 스킬             |
| 3. 플러그인 마켓플레이스                    | 자동 갱신(켜야 함)       | 마켓플레이스 추가, 설치 + git 인증(비공개 저장소일 때) | 여러 저장소와 여러 사람이 쓰는 스킬 |


- 자동 갱신은 서드파티 마켓플레이스에서 기본 꺼짐. `/plugin` → Marketplaces에서 켬.
  - 세션 중 백그라운드로 받고, `/reload-plugins`나 다음 실행 때 반영.

## 함정

- MCP 조회: 스킬을 설치하지 않고, 로컬에 클론한 정본 저장소를 MCP 서버가 읽는 방식.
- 심볼릭 링크와 MCP 조회도 결국 로컬 체크아웃을 읽음. pull하지 않으면 사본과 똑같이 낡음.
- 스킬과 MCP 조회는 불리는 계기가 다름.
  - 스킬: `description`이 항상 컨텍스트에 있어 작업이 조건과 맞으면 자동으로 불림.
  - MCP: 범용 도구 설명만 있어서, 지침 파일의 한 줄을 모델이 떠올려야 불림.
