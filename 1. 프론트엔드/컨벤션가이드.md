# Convention

## 파일명
- 파일/폴더 이름 : `kebab-case.ts`
- React 컴포넌트 : `PascalCase.tsx`
- 클래스 이름 : `class PascalCase {}`
- 변수/함수 : `camelCase`
- 상수 : `UPPER_SNAKE_CASE`

> 💡 파일명을 kebab-case로 하는 이유?
> - macOS/Windows 기본 파일 시스템이 대소문자가 약한 경우가 많음.(빌드 오류 발생 확률있음)

## 접두사
파일명에는 슬라이스명 접두사를 붙이지 않고, 심볼명에는 도메인 접두사를 유지함.

- 파일명 : 경로가 이미 소속을 표현하므로 접두사 생략 → `pages/task-plan/model/form.ts` (`task-plan-form.ts` 아님)
- 훅 파일명 : 예외 없이 동일하게 적용 → `use-preview.ts` (`use-task-plan-preview.ts` 아님)
- 심볼명(변수/함수/타입/상수) : 도메인 접두사 유지 → `useTaskPlanPreview`, `TaskPlanFormValues`, `TASK_PLAN_DETAIL_LABELS`
- 파일명과 심볼명이 어긋나는 것은 감수 → `use-preview.ts`가 `useTaskPlanPreview`를 내보내는 형태 허용

> 💡 심볼명에만 접두사를 유지하는 이유?
> - 심볼은 사용 지점에 경로가 드러나지 않아서 소속을 스스로 표현해야 함.
> - 심볼은 라이브러리/전역 네임스페이스와 충돌함. (`useTaskPlanSearchParams` → 접두사를 떼면 `react-router-dom`의 `useSearchParams`와 겹침)

접두사를 제거해 다른 슬라이스와 basename이 겹치는 것은 허용. (import 문에 항상 경로가 함께 드러나므로 구분 가능)

### 예외
- React 컴포넌트 파일은 도메인 접두사 유지. 접두사를 떼면 `Page.tsx`, `Search.tsx` 처럼 식별력이 사라짐 → `TaskPlanPage.tsx`, `TaskPlanSearch.tsx`
- 슬라이스 대표 파일은 슬라이스명을 그대로 사용 가능 → `entities/task-plan/model/task-plan.ts`, `entities/education/model/education.ts`
- 공개 API(`index.ts`)로 내보내는 심볼은 접두사 필수. 다른 슬라이스가 자기 문맥에서 사용하므로 접두사가 유일한 소속 표시 → `TaskPlanStatus`, `TASK_PLAN_STATUS_LABELS`

## 함수명
`save`냐 `add`냐는 단어 선택 문제가 아니라 그 함수가 어느 층에 있느냐의 문제임. 층을 먼저 정하면 동사는 따라옴.

| 층 | 동사 | 예시 |
| --- | --- | --- |
| API 함수, CRUD | `create`, `update`, `delete`, `get` | `createTask`, `updateTask`, `deleteTask`, `getTask`, `getTaskList` |
| API 함수, 비CRUD | 도메인 동사 | `submitTaskPlan`, `publishNotice`, `cancelOrder` |
| 뮤테이션 훅 | `use` + API 함수명 | `useCreateTask`, `useSubmitTaskPlan` |
| 조회 훅 | `use` + API 함수명 | `useGetTaskList` (저장소 관례를 따름) |
| UI 핸들러 | `handle` + 버튼 라벨 | `handleSave`, `handleSubmit` |
| 로컬 상태/컬렉션 | `add`, `remove`, `set`, `toggle`, `reset` | `addRow`, `removeRow`, `setFilter` |
| 계산 함수 | 명사구 허용 | `taskSummary`, `visibleTaskList` |

- 서버에 새로 저장하면 `create`. `saveTask`, `addTask` 아님 → `createTask`
- `save`는 id 유무로 POST/PATCH를 분기하는 함수와 화면 핸들러에만 허용. 분기 조건은 TSDoc `@remarks`에 기재
- `add`/`remove`는 로컬 컬렉션과 관계 추가 엔드포인트에만 허용 → `POST /teams/{id}/members`는 `addTeamMember`
- 조회는 `get`으로 통일. `fetch`/`load`/`retrieve` 혼용 금지. 단건 `getTask`, 목록 `getTaskList`
- 서버에서 지우면 `delete`, 화면에서 빼면 `remove`
- 수정은 `update`로 고정. `edit`은 UI 모드에만 → `isEditing`, `handleEdit`
- 불리언 반환은 `is`/`has`/`can` → `isTaskEditable`, `canSubmitTaskPlan`
- 부수효과가 있으면 명령형 동사로 시작 → `getTaskList()` (`taskList()` 아님)

> 💡 `save`를 API 함수에 쓰지 않는 이유?
> - [Rails](https://api.rubyonrails.org/classes/ActiveRecord/Persistence.html)와 [Mongoose](https://mongoosejs.com/docs/api/document.html) 문서가 `save`를 "신규면 생성, 아니면 수정"으로 정의한 upsert 어휘임. ORM은 신규 여부를 프레임워크가 알아서 이 모호함이 비용이 아니지만, 프론트 API 함수는 그 판단을 아무도 안 해줌. 분기가 없는 함수에 붙이면 호출부에서 POST인지 PATCH인지 알 수 없음.

> 💡 `add`를 POST에 쓰지 않는 이유?
> - `Set.prototype.add`([MDN](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Set/add)), Redux `todoAdded`([Style Guide](https://redux.js.org/style-guide/))처럼 `add`는 이미 있는 컬렉션에 넣는 동작임. 목록 상태 조작 함수와 이름이 충돌함.

> 💡 CRUD로 안 떨어지는 요청에 도메인 동사를 쓰는 이유?
> - [AIP-136](https://google.aip.dev/136)이 커스텀 메서드 이름을 "verb followed by a noun"으로 정하고 표준 동사(Get/List/Create/Update/Delete) 재사용을 금지함. 상신을 `createTaskPlanSubmission`으로 비틀면 실제 도메인 동작이 가려짐.

> 💡 동사를 HTTP 메서드와 1:1로 맞추는 이유?
> - [AIP-133](https://google.aip.dev/133)이 "The RPC's name must begin with the word `Create`", "The HTTP verb must be `POST`"로 이름과 메서드를 한 쌍으로 못 박음. Stripe도 Create/Update/Retrieve/List/Delete로 같은 어휘를 씀. 호출부에서 이름만 보고 어떤 요청이 나가는지 알 수 있어야 함.

## 주석
주석은 항상 함수 위에 달아야함. (vscode에서 커서 툴팁으로 설명 작용 DX 고려, TSDoc 적용)
https://tsdoc.org/

```tsx
import toast from './toast';

/**
 * 텍스트를 클립보드에 복사한 뒤, 성공 시 토스트 메시지를 표시합니다.
 *
 * @param copyText - 클립보드에 복사할 텍스트
 * @param successMessage - 복사 성공 시 표시할 토스트 메시지
 *
 * @returns void
 *
 * @example
 * copyToClipboard('https://example.com', '링크가 복사되었습니다!');
 * // 클립보드에 'https://example.com'이 복사되고, 성공 메시지가 토스트로 표시됨
 */
const copyToClipboard = (copyText: string, successMessage: string) => {
  if (copyText) {
    navigator.clipboard.writeText(copyText).then(
      () => {
        if (successMessage) {
          toast(successMessage, { variant: 'success' });
        }
      },
      (error) => {
        console.error('복사 실패:', error);
      },
    );
  }
};

export default copyToClipboard;
```
