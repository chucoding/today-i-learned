# 스크롤바
커스텀 스크롤바를 만들 때 엔진마다 갈리는 지점들

브라우저는 스크롤바 스타일 API 를 **두 갈래**로 갖는다.

| API | 지원 | 제어 범위 |
|---|---|---|
| `::-webkit-scrollbar` 계열 의사요소 | Chromium, Safari | 두께·색·모서리·트랙 여백까지 세밀하게 |
| `scrollbar-width` / `scrollbar-color` (표준) | Firefox, Chromium 121+ | `auto`/`thin`/`none` 과 `thumb track` 색만 |

Firefox 는 의사요소를 지원하지 않으므로 둘 다 써야 하는데, **그냥 같이 쓰면 안 된다.**

## 표준 프로퍼티가 있으면 Chromium·Safari 는 의사요소를 통째로 무시한다
`scrollbar-width` 나 `scrollbar-color` 중 **하나라도** 지정돼 있으면 Chromium 은 `::-webkit-scrollbar` 규칙 전체를 버리고 표준 프로퍼티만 따른다. 실측값이다.

| 선언 | Chromium 실효 두께 |
|---|---|
| `::-webkit-scrollbar { width: 30px }` 만 | 30px |
| `::-webkit-scrollbar { width: 8px }` 만 | 8px |
| `scrollbar-width: thin` + 의사요소 8px | **11px** (thin 의 기본 두께) |
| `scrollbar-color` 만 + 의사요소 8px | **15px** (기본 두께) |
| 표준 프로퍼티를 Firefox 로 격리 + 의사요소 8px | 8px |

의사요소로 정성껏 맞춘 스펙이 **조용히 전부 죽는다.** 에러도 경고도 없어서 알아채기 어렵다.

해결은 표준 프로퍼티를 Firefox 에만 적용하는 것이다.

```css
/* 모든 브라우저: 의사요소 */
.list::-webkit-scrollbar { width: 4px }
.list::-webkit-scrollbar-track { background: transparent }
.list::-webkit-scrollbar-thumb { background: #555d6d80; border-radius: 10px }

/* Firefox 에서만 */
@supports (-moz-appearance: none) {
  .list { scrollbar-width: thin; scrollbar-color: #555d6d80 transparent }
}
```

> ⚠️ Firefox 판별에 `@supports not selector(::-webkit-scrollbar)` 를 쓰면 안 된다. **Firefox 가 이 셀렉터를 지원한다고 보고**해서(`CSS.supports('selector(::-webkit-scrollbar)') === true`) 조건이 성립하지 않는다. `-moz-appearance` 는 Firefox 만 `true` 를 반환한다(Chromium·WebKit `false`).

## `::-webkit-scrollbar-thumb` 는 opacity 와 transition 을 무시한다
스크롤바 의사요소는 적용 가능한 속성이 제한적이다. `opacity` 와 `transition` 이 빠져 있다.

```css
/* 안 먹는다 */
::-webkit-scrollbar-thumb {
  background: #555d6d;
  opacity: .5;                    /* 무시 → 100% 로 진하게 나옴 */
  transition: opacity .3s ease;   /* 무시 */
}
::-webkit-scrollbar-thumb:hover { opacity: .7 }  /* 무시 */
```

반투명은 **색 자체에 알파를 넣어야** 한다. 토큰을 유지하려면 `color-mix` 가 편하다.

```css
background: color-mix(in srgb, var(--fg-neutral-muted) 50%, transparent);
```

같은 이유로 hover 시 서서히 진해지는 전환 효과는 만들 수 없다. 색만 바꿀 수 있다.

## 트랙보다 얇은 thumb 를 border 로 만들면 모서리가 잘린다
"트랙 8px, thumb 4px" 처럼 thumb 를 얇게 만들 때 흔히 쓰는 방법이 투명 border + `background-clip` 이다.

```css
::-webkit-scrollbar { width: 8px }
::-webkit-scrollbar-thumb {
  border-radius: 10px;
  border-right: 4px solid transparent;
  background-clip: content-box;   /* 왼쪽 4px 만 칠함 */
}
```

폭은 의도대로 4px 이 되지만, **`border-radius` 는 border box(8px) 기준으로 그려진 뒤 content box(4px) 로 잘린다.** 결과는 한쪽 면이 수직으로 잘린 **반쪽 pill** 이다. 둥근 thumb 를 의도했다면 눈에 띈다.

thumb 를 옆으로 밀어야 한다면 border 가 아니라 **스크롤 컨테이너 자체를 그만큼 좁혀서** 트랙 위치를 옮긴다. 네이티브 스크롤바는 항상 컨테이너의 끝에 붙으므로, 컨테이너가 4px 좁아지면 트랙도 4px 안쪽으로 들어온다.

## 실효 두께는 `scrollbar-gutter: stable` 로 잰다
macOS 는 기본이 오버레이 스크롤바라 레이아웃 공간을 먹지 않는다. `offsetWidth - clientWidth` 가 항상 `0` 이라 **두께를 잴 수 없다.**

`scrollbar-gutter: stable` 을 임시로 걸면 오버레이라도 공간을 예약하므로, 그 차이가 곧 실효 두께다.

```js
el.style.scrollbarGutter = 'stable'
const width = el.offsetWidth - el.clientWidth   // 실효 두께
el.style.scrollbarGutter = ''
```

위의 "표준 프로퍼티가 의사요소를 무시한다"도 이 방법으로 확인했다. 어느 선언이 실제로 이겼는지 눈이 아니라 숫자로 판정할 수 있다.

> 💡 headless Chromium 은 macOS 에서 **스크롤바를 아예 페인트하지 않는다.** `width: 30px` 에 빨간 thumb 를 줘도 스크린샷에 안 나온다. 스크롤바 모양을 눈으로 확인해야 한다면 Playwright 의 WebKit 을 쓰면 그려진다.
