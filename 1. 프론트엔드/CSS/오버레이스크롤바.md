## 네이티브 스크롤바의 한계

- OS별 네이티브 스크롤바 전략 다름.
  - Windows 기본 스크롤바 : **클래식 스크롤바**(항상 거터에 놓여 자리를 차지하는 스크롤바)
    - 15~17px 폭을 콘텐츠 영역에서 가져감.
    - 같은 화면이 저해상도 Windows에서만 좁아지고 두꺼운 바가 보임.
  - macOS : 트랙패드 기본값은 오버레이 방식 (폭이 0)
    - 마우스 연결이나 '스크롤 막대 보기: 항상' 설정에서는 자리를 차지함.

## CSS 한계

- 두께 변경만 가능하고 자리 제거는 불가 (CSS로는 얇게만 가능)
  - Windows에서 폭 0 오버레이 불가
  - `overflow: overlay`도 Chrome 114부터 `auto`의 별칭이라 효과 없음.
- 페이드 인·아웃
- "스크롤 중일 때만 노출" (스크롤 중 상태를 잡는 선택자가 없음)
- 트랙 클릭 시 클릭 지점으로 이동 (네이티브는 한 화면씩 점프)

## 오버레이 구현 방법

1. **네이티브 스크롤은 그대로 두고 바만 숨김 처리 (**키보드 스크롤, 휠, 스크린리더가 유지됨.)
2. 그 위에 트랙과 thumb 요소를 `position: absolute`로 얹고, `scroll` 이벤트와 `ResizeObserver`로 위치를 맞춤
3. thumb 길이와 위치

```text
thumb 길이 = max(트랙 길이 × 뷰포트 ÷ 콘텐츠, 최소 길이)
thumb 위치 = scrollTop ÷ (콘텐츠 − 뷰포트) × (트랙 길이 − thumb 길이)
```

최소 길이(예: 32px)에 걸리면 비례식이 깨진다. 그래서 위치는 **남은 트랙 이동 거리**(`트랙 − thumb`)에 스크롤 가능 거리를 다시 대응시킨다

4. **히트 영역은 트랙 전체 폭**으로 설정. 4px thumb를 직접 집게 하면 포인터로 잡기 어려움(권장 최소 8px)

## 라이브러리 비교


| 항목       | OverlayScrollbars 2.16        | Radix ScrollArea 1.4                 | Base UI ScrollArea 1.9               |
| -------- | ----------------------------- | ------------------------------------ | ------------------------------------ |
| 적용 방식    | **기존 요소에 초기화**                | Root, Viewport, Scrollbar, Thumb로 감쌈 | 감쌈                                   |
| 최소 thumb | CSS 변수 `--os-handle-min-size` | `Math.max(thumbSize, 18)` 하드코딩       | `MIN_THUMB_SIZE = 16` 하드코딩           |
| 트랙 클릭    | `clickScroll` 플러그인            | 클릭 지점에 thumb 중심이 오도록 이동              | 클릭 지점으로 이동                           |
| 자동 숨김    | `autoHide`, `autoHideDelay`   | `type`, `scrollHideDelay`            | `data-hovering`, `data-scrolling` 속성 |
| 의존성      | 없음                            | radix 내부 패키지 10개                     | 5개                                   |


- **OverlayScrollbars를 고른 이유는 적용 방식.** 감싸는 방식은 AG Grid나 MUI Table처럼 DOM을 직접 만들지 않는 서드파티 내부 스크롤 영역에 적용 불가
- 최소 길이를 Figma 스펙 값(32px, 24px)으로 바꿀 수 있는 것도 OverlayScrollbars뿐임.
