## 폼 전송 네비게이션

- 폼 제출은 페이지 이동. 응답이 `target`이 가리키는 창(기본은 현재 창)의 새 문서가 됨.
  - MDN form: `target`은 제출 후 응답을 표시할 위치.
- 창에 띄우는 폼 POST의 응답은 브라우저가 문서로 표시할 수 있는 형식(주로 HTML)이어야 함.
- 서버를 어디에 배포하든 같은 브라우저 네비게이션 규칙

## GET과 POST 크기 한계

| | GET | POST |
|---|---|---|
| 데이터 위치 | action URL 뒤 쿼리 문자열(`?`) | 요청 본문 |
| 크기 한계 | URL 길이. 표준 고정값 없이 브라우저와 서버 구현이 정함 | 본문 크기. 서버 설정이 정함 |

- RFC 9110: 송신자와 수신자 모두 최소 8000옥텟 길이의 URI 지원 권장.
- 데이터가 커서 URL에 실을 수 없으면 POST 본문으로 보냄. 요청 횟수가 아니라 요청 크기 문제.

## 대안

| 방식 | 동작 | 대가 |
|---|---|---|
| 폼 POST 네비게이션 | 데이터를 본문에 실어 창을 엶 | 서버가 문서로 표시할 응답(주로 HTML)을 만들어야 함 |
| 먼저 저장 후 id로 GET | `fetch`로 저장하고 받은 id를 URL에 넣어 창을 엶 | 요청 두 번. 임시 데이터 저장과 정리 필요 |
| 정적 페이지와 `postMessage` | 정적 페이지를 연 뒤 연 쪽 창이 데이터 전달 | 새 창의 준비 완료 신호를 기다려야 함. 새로고침하면 데이터 사라짐 |
