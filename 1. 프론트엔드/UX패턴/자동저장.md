## 낙관적 업데이트

- 서버 응답을 기다리지 않고 화면 먼저 바꿈. 실패하면 되돌림.
  - TanStack Query: mutation 완료 전에 UI를 갱신하고, 실패하면 롤백.

## write-behind

- 로컬에 먼저 쓰고 원본 저장소에는 나중에 비동기로 모아서 씀.
  - Ehcache: write-behind는 원본 저장소에 비동기로 쓰는 방식.
- 원래 서버 캐시와 DB 사이의 용어. 자동저장은 같은 구조를 브라우저와 서버 사이에 적용한 것.
- 읽기는 stale-while-revalidate 방식. 로컬 값을 먼저 보여 주고 서버 값으로 맞춤.
  - web.dev: 캐시 응답을 바로 쓰고 재검증 요청은 뒤에서 보냄.

## 요청 줄이기

| | debounce | throttle |
|---|---|---|
| 동작 | 짧은 간격의 연속 호출을 한 번으로 합침 | 정해진 속도 이상으로 실행하지 않음 |
| 실행 시점 | 마지막 호출 뒤 대기 시간이 지나면(트레일링), 또는 첫 호출 때(리딩) | 간격마다 최대 한 번 |
| 쓰임 | 입력이 끝난 뒤 저장, 검색 | 스크롤, 리사이즈 |

- MDN Debounce: 특정 간격 안에 너무 가깝게 일어난 동작을 버리고 한 번의 호출로 합침.
- MDN Throttle: 동작이 일정 속도로만 실행되도록 처리를 늦춤.
- 자동저장은 트레일링 debounce. 입력이 멈춘 뒤 한 번만 보냄.
- 같은 값 건너뛰기: 마지막으로 보낸 값과 같으면 보내지 않음
- 한 번에 요청 하나: 진행 중에 바뀐 값은 끝난 뒤 최신 값만 보냄. 마지막 의도가 이김.
- 멱등 API: 통째로 교체하는 PUT. 중복이나 재시도로 여러 번 가도 결과 같음.
- 클라이언트 쪽 제한은 정상 화면의 과도한 호출만 줄임. 화면을 거치지 않고 API를 직접 부르는 호출은 막지 못해 DDoS 방어 수단이 아님.

## 페이지 이탈 시 전송

- 감지 시점: `visibilitychange`의 `hidden`을 주로, `pagehide`를 보조로
  - MDN visibilitychange: `hidden` 전환이 페이지가 확실히 관찰할 수 있는 마지막 이벤트.
  - MDN unload: 특히 모바일에서 `unload`는 발생이 보장되지 않음.
- 전송 수단

  | | `navigator.sendBeacon` | `fetch` `keepalive: true` |
  |---|---|---|
  | 메서드 | POST만 | 제한 없음 |
  | 크기 | 대기 중인 데이터 합계 64KiB | 본문 64KiB |

- `sendBeacon`의 `true`는 전송 대기열에 넣었다는 뜻이지 서버 수신 확인이 아님.
