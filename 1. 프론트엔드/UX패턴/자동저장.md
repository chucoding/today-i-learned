## 낙관적 업데이트

- 서버 응답을 기다리지 않고 화면 먼저 바꿈. 실패하면 되돌림.
  - TanStack Query: mutation 완료 전에 UI를 갱신하고, 실패하면 롤백.

## write-behind

- 로컬(localStorage)에 먼저 쓰고 원본 저장소에는 나중에 비동기로 모아서 씀.
  - Ehcache: write-behind는 원본 저장소에 비동기로 쓰는 방식.
- 원래 서버 캐시와 DB 사이의 용어. 자동저장은 같은 구조를 브라우저와 서버 사이에 적용한 것.
- 로컬을 두는 이유: 서버 전송이 실패해도 같은 브라우저에는 마지막 입력이 남음.
- 읽기는 stale-while-revalidate 방식. 로컬 값을 먼저 보여 주고 서버 값으로 맞춤.
  - web.dev: 캐시 응답을 바로 쓰고 재검증 요청은 뒤에서 보냄.

## 요청 줄이기

| | debounce | throttle |
|---|---|---|
| 동작 | 짧은 간격의 연속 호출을 한 번으로 합침 | 정해진 속도 이상으로 실행하지 않음 |
| 실행 시점 | 마지막 호출 뒤 대기 시간이 지나면(트레일링), 또는 첫 호출 때(리딩) | 간격마다 최대 한 번 |
| 쓰임 | 입력이 끝난 뒤 저장, 검색 | 스크롤, 리사이즈 |

- MDN Debounce: 특정 간격 안에 너무 가깝게 일어난 동작을 버리고 한 번의 호출로 합침.
- MDN Throttle: 동작이 일정 속도로만 실행되도록 처리를 늦춤.
- 자동저장은 트레일링 debounce. 입력이 멈춘 뒤 한 번만 보냄.
- 같은 값 건너뛰기: 마지막으로 보낸 값과 같으면 보내지 않음
- 싱글플라이트(저장 요청 하나씩 보내기): 앞 저장 요청의 응답이 오기 전에는 다음 저장 요청을 보내지 않음. 그사이 값이 또 바뀌면 응답이 온 뒤 최신 값 하나만 보냄.
  - 없으면: 값 1을 저장하는 요청 A와 값 2를 저장하는 요청 B가 함께 나가고, A가 늦게 도착하면 서버에 옛 값 1이 남음.
  - debounce와 역할 다름. debounce는 요청 수를 줄이고, 이 방식은 요청이 겹치지 않게 함. 응답이 debounce 대기 시간보다 늦으면 debounce만으로는 요청이 겹침.
- 멱등 API: 통째로 교체하는 PUT. 중복이나 재시도로 여러 번 가도 결과 같음.
- 클라이언트 쪽 제한은 정상 화면의 과도한 호출만 줄임. 화면을 거치지 않고 API를 직접 부르는 호출은 막지 못해 DDoS 방어 수단이 아님.

## 즉시 전송

- 필요한 이유: debounce 대기 중에 페이지를 닫으면 아직 보내지 않은 값이 서버에 반영되지 않음. 그래서 아래 시점에는 debounce 대기 없이 바로 보냄(flush).
- 감지 시점: `visibilitychange`의 `hidden`을 주로, `pagehide`를 보조로
  - MDN visibilitychange: `hidden` 전환이 페이지가 확실히 관찰할 수 있는 마지막 이벤트.
  - MDN unload: 특히 모바일에서 `unload`는 발생이 보장되지 않음.
  - `visibilitychange`는 닫기 말고도 탭 전환이나 창 최소화로 화면이 가려질 때 발생.
- 인쇄 직전: `beforeprint`
  - MDN beforeprint: 문서를 인쇄하거나 인쇄 미리보기를 열기 직전에 발생.
  - 화면의 인쇄 버튼, 단축키, 브라우저 메뉴 중 어느 경로로 인쇄해도 같은 이벤트. 인쇄 시점의 서버 값을 맞추는 보조 flush.
- `keepalive`: 보통 요청은 페이지가 닫히면 취소되지만, `keepalive: true` 요청은 페이지가 사라진 뒤에도 브라우저가 끝까지 보냄.
  - MDN RequestInit: 요청을 시작한 페이지가 요청 완료 전에 언로드되어도 요청을 유지할지 정함.
- 전송 수단

  | | `navigator.sendBeacon` | `fetch` `keepalive: true` |
  |---|---|---|
  | 메서드 | POST만 | 제한 없음 |
  | 크기 | 64KiB 한도 | 64KiB 한도 |

- 선택 기준: 저장 API가 POST이고 인증 헤더 같은 커스텀 헤더가 필요 없으면 `sendBeacon`, 그 외는 `fetch` `keepalive`. `sendBeacon`은 요청 헤더를 지정할 수 없음.

- `sendBeacon`의 `true`는 전송 대기열에 넣었다는 뜻이지 서버 수신 확인이 아님.
