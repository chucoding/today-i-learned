# 팝오버 배치
앵커에 붙어 떠 있는 요소(드롭다운·메뉴·툴팁·피커)를 **어디에 놓을지** — 표준 어휘와 폴백 순서, 그리고 2026년에 무엇으로 구현할지

## 배치는 "변 + 정렬" 두 축으로 말한다
라이브러리들이 쓰는 어휘가 같다. `bottom-start` 는 **아래쪽 변**에 붙이고 **시작(왼쪽) 정렬**한다는 뜻이다.

| 라이브러리 | 표기 | 기본값 |
|---|---|---|
| Floating UI | `placement: 'bottom-start'` | `'bottom'` (정렬 미지정 = 가운데) |
| Radix UI | `side` + `align` | `side="bottom"` `align="center"` |

여기에 두 종류의 상수가 붙는다. **앵커와의 간격**(Floating UI `offset()`, Radix `sideOffset`)과 **경계와 유지할 여백**이다. 후자는 이름이 제각각이라 헷갈린다.

| 라이브러리 | 경계 여백 | 기본값 |
|---|---|---|
| Floating UI | `shift({padding})` · `flip({padding})` · `size({padding})` | `0` |
| Radix UI | `collisionPadding` | Popover `0` / Select `10` |
| MUI | `marginThreshold` | `16` |

## 폴백 순서의 표준형은 flip → shift → size
공간이 부족할 때 무엇을 먼저 포기할지가 곧 배치 설계다. Floating UI 튜토리얼이 제시하는 기본 조합이 `offset` + `flip` + `shift` 이고, 여기에 크기까지 줄여야 하면 `size` 가 붙는다.

| 미들웨어 | 하는 일 | 놓치기 쉬운 기본값 |
|---|---|---|
| `flip` | 지정한 변이 넘치면 **반대 변**으로 뒤집는다 | `fallbackPlacements` 는 반대 변 하나뿐. **`fallbackAxisSideDirection` 기본 `'none'`** — 즉 좌우로 비켜서는 폴백은 **꺼져 있다.** 아무 데도 안 맞으면 `fallbackStrategy: 'bestFit'`(기본)으로 가장 덜 넘치는 곳 |
| `shift` | 변은 유지한 채 **정렬 축으로 밀어** 넘침을 없앤다 | `mainAxis: true`, **`crossAxis: false`** (켜면 앵커와 겹칠 수 있음), `limiter` 미지정. `limitShift()` 를 주면 앵커에서 떨어지기 전에 멈춘다 |
| `size` | 남은 공간(`availableWidth`/`availableHeight`)을 알려준다 | `apply` 를 직접 써야 적용된다. **음수가 나올 수 있어 0으로 클램프** 필요 |

두 가지 순서 규칙이 있다.

- **`offset` 은 배열 맨 앞, `arrow`·`hide` 는 맨 뒤.** 미들웨어는 앞의 결과 좌표를 이어받는다
- **`size` 를 `flip` 뒤에 두면 `bestFit`, 앞에 두면 `initialPlacement`** 가 된다. 뒤에 두면 "배치를 먼저 고르고 그 방향의 남은 공간에 맞춰 줄이는" 동작이 되고, 앞에 두면 "최소 크기까지 줄여보고 그래도 안 되면 뒤집는" 동작이 된다. 양쪽 `padding` 은 같은 값으로 맞춘다
- `flip` 과 `autoPlacement` 은 **같은 배열에 함께 쓸 수 없다.** 전자는 선호 배치 우선, 후자는 최대 공간 우선이라 목적이 충돌한다

Radix Popper 내부도 정확히 같은 구성이다 — `offset → shift → flip → size`, `strategy: 'fixed'`. 즉 Radix 를 쓰는 것은 이 조합을 기본값으로 받는 것과 같다.

공간이 아예 부족할 때 크기를 줄이는 쪽은 → [캘린더.md](./캘린더.md#위·아래-어디에도-안-들어가면-남은-공간만큼-잘라-스크롤이-표준이다)

## 클리핑 조상과 z-index — 포털·fixed·top layer
앵커 옆에 그냥 `absolute` 로 붙이면 `overflow: hidden` 인 조상에서 잘리고, 조상이 만든 스태킹 컨텍스트 때문에 z-index 싸움이 시작된다. 해법이 세 단계로 발전해 왔다.

1. **포털 + `position: fixed`** — Floating UI 문서도 "Using the `'fixed'` strategy will 'break' the floating element out of its parent clipping context in the majority of cases" 라고 안내한다. 다만 포털 대상을 `body` 로 고정하면 모달 포커스 트랩 밖으로 나가므로 조상을 보고 정해야 한다(→ [캘린더.md](./캘린더.md#모달-안에서-여는-피커는-esc포털z-index-세-가지가-겹친다))
2. **z-index 를 조상보다 높게 계산** — 손으로 하면 조상을 훑어 최댓값+1 같은 계산이 필요하다
3. **top layer (Popover API)** — `popover` 속성을 쓰면 표시될 때 요소가 **top layer 로 올라가** z-index 경쟁과 클리핑이 구조적으로 사라진다. Esc 닫기·바깥 클릭 닫기(light dismiss)·포커스 복귀가 딸려 온다

## 앵커가 사라지면 어떻게 할지도 배치의 일부다
스크롤 컨테이너 안의 앵커가 밀려 나가면 팝오버만 허공에 뜬다. 라이브러리마다 기본값이 다르다.

| 기능 | Floating UI | Radix |
|---|---|---|
| 앵커가 가려졌는지 판정 | `hide({strategy: 'referenceHidden'})` → `middlewareData.hide.referenceHidden` | `hideWhenDetached` (**기본 `false`**) |
| 앵커가 경계를 걸칠 때 | — | `sticky: 'partial'`(기본) |

CSS 표준에도 대응이 생겼지만 **아직 쓰면 안 된다.** `position-visibility` 의 키워드가 `anchors-visible` → `anchor-visible` 로 개명 중이라 공개 WD·에디터 초안·구현이 서로 다르다(단수형은 Safari 27 베타에만 있다). 게다가 판정 기준이 IntersectionObserver 와 같아서, **팝오버가 앵커와 같은 스크롤러 안에 있으면 애초에 숨겨지지 않는다** — top layer 로 올린 경우에만 의미가 있다.

## 접근성 기준은 APG 가 아니라 WCAG 에 있다
WAI-ARIA APG 의 Combobox·Menu·Listbox·Dialog·Tooltip 패턴 문서에는 **시각적 배치에 관한 지침이 한 건도 없다.** 구성이 `About / Examples / Keyboard Interaction / WAI-ARIA Roles, States, and Properties` 뿐이고 시각 디자인 절 자체가 없다. flip·shift 는 명세가 요구한 규칙이 아니라 아래 성공 기준을 만족시키려고 업계가 수렴한 수단이다.

| 기준 | 배치에 주는 실제 제약 |
|---|---|
| **2.4.11 Focus Not Obscured (AA)** | "When a user interface component receives keyboard focus, the component is **not entirely hidden** due to author-created content." Understanding 문서가 드롭다운·데이트피커를 직접 지목하되, **비영속 팝오버는 실패로 보지 않는다.** 대신 "an open dropdown that **does not close when no longer focused** is not following this convention" — 요구는 좌표가 아니라 **생명주기(포커스를 잃으면 닫아라)** 다 |
| **1.4.10 Reflow (AA)** | 320 CSS px 폭에서 2차원 스크롤 금지 → "화면 밖으로 나가면 안으로 밀어 넣어라(shift)" 의 근거 |
| **1.4.4 Resize Text (AA)** | 200% 확대에서 잘리거나 가려지면 위반 → 고정 px 높이 대신 내부 스크롤 |
| **1.4.13 Content on Hover or Focus (AA)** | hover/focus 로 뜨는 것에만 적용(클릭으로 여는 피커는 대상 아님). Dismissible 면제 조건이 "**트리거 자신을 포함해** 의미 있는 콘텐츠를 가리지 않을 것" |

## 따라다니게 하는 비용 — autoUpdate
배치는 한 번 계산하고 끝이 아니다. 스크롤·리사이즈·레이아웃 시프트마다 다시 계산해야 한다. Floating UI `autoUpdate` 의 기본값이 사실상 이 목록의 표준이다.

| 옵션 | 기본값 | 감지 대상 |
|---|---|---|
| `ancestorScroll` | `true` | 스크롤 조상의 스크롤 |
| `ancestorResize` | `true` | 조상 리사이즈(`resize` 이벤트) |
| `elementResize` | `true` | 앵커·플로팅 요소 크기 변화(`ResizeObserver`) |
| `layoutShift` | `true` | 레이아웃 시프트로 앵커가 움직인 경우 |
| `animationFrame` | **`false`** | 매 프레임. "While optimized for performance, **it should be used sparingly**" — 앵커가 `transform` 으로 애니메이션할 때만 |

문서가 굵게 경고하는 것은 옵션이 아니라 **생명주기**다.

> "It's important that this function is only called/set-up when the floating element is open on the screen, and cleaned up when it's removed. **Otherwise, it can cause severe performance degradation**, especially with many floating elements being created."

React 라면 `whileElementsMounted: autoUpdate` 가 등록·해제를 대신 해주지만, 조건이 있다. **"Only use this option if your floating element is _conditionally rendered_, not hidden with CSS."** CSS 로 숨기는 구조라면 직접 effect 로 관리해야 한다.

## 2026년에 새로 만든다면
- **컨테이너는 Popover API 를 쓴다.** Chrome/Edge 114(2023-05), Safari 17(2023-09), Firefox 125(2024-04) — 3엔진 모두 2년 넘었다. top layer 로 클리핑·z-index 문제가 사라지고 light dismiss·Esc·포커스 복귀가 공짜다
- **위치 계산은 아직 Floating UI 가 주력이고, CSS Anchor Positioning 은 점진 강화로 얹는다.** 코어(`anchor-name`/`anchor()`)는 Chrome 125(2024-05)·Safari 26(2025-09)·Firefox 147(2026-01)로 다 모였지만, 실제로 필요한 세부가 훨씬 늦다 — `position-area` 물리 키워드 단독값 Chrome 144(2026-01), `position-anchor` 초깃값 정합 Chrome 151(2026-07)·Firefox 151(2026-05)·Safari 27(베타). caniuse 집계 지원율 약 84.8%
- `@supports (anchor-name: --x)` 로 분기하고, CSS 경로에서는 명세가 직접 제시하는 드롭다운 패턴을 쓴다

```css
.list {
  position: fixed;
  position-anchor: --trigger;
  position-area: block-end span-inline-end;      /* 아래쪽에 붙임 */
  position-try-fallbacks: --bottom-scrollable, flip-block, --top-scrollable;
  position-try-order: most-height;               /* 공간이 더 넓은 쪽 우선 */
}
@position-try --bottom-scrollable { align-self: stretch; }   /* 남은 높이에 맞춰 늘림 */
@position-try --top-scrollable { position-area: block-start span-inline-end; align-self: stretch; }
```

`flip-block`(위아래 뒤집기)·`flip-inline`(좌우 뒤집기)·`flip-start`(대각 반사 = 인접 변으로) 가 `flip` 미들웨어를, `position-try-order: most-height` 가 `fallbackStrategy: 'bestFit'` 을, `align-self: stretch` 가 `size` 를 대신한다. **선언형으로 같은 폴백 체계를 표현할 수 있다는 것이 핵심이고, 어휘가 라이브러리와 1:1로 대응한다.**
