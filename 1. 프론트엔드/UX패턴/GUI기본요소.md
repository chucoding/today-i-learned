# GUI 기본 요소
거의 모든 화면은 10가지 표준 요소로 구성되며, 관례를 지키는 것이 학습 비용을 줄이는 가장 강력한 도구

> 출처: [10 GUI Design Elements That Make Up Every User Interface](https://www.uxtigers.com/post/gui-widgets) (Jakob Nielsen) / [GeekNews](https://news.hada.io/topic?id=32160)

## 3가지 대원칙
86개의 세부 가이드라인은 결국 아래 3가지로 요약됨

- 사용자가 **기억하게** 만들지 않는다 (인지 부하)
- 사용자가 **추측하게** 만들지 않는다 (불확실성)
- 사용자가 **기다리게** 만들지 않는다 (지연)

## 피츠의 법칙(Fitts's Law)
1954년에 정립된 법칙으로, 목표물까지의 **거리가 멀수록** 그리고 **크기가 작을수록** 조작 시간이 길어짐

- 자주 쓰는 액션은 크고 가깝게 배치
- 화면 가장자리는 높이가 무한한 것과 같음 (macOS 메뉴바가 화면 최상단에 붙어 있는 이유)
- 터치 타겟은 최소 1cm × 1cm 확보

## 10가지 요소

### 1. 버튼(Button)
클릭 시 하나의 명령을 실행하며, 화면이 아닌 실제 상태(구매·저장·전송·삭제)를 바꿈

- 눌리는 것처럼 보이게 하고 상태 변화를 명확히 표현
- 레이블은 결과 중심으로 작성 (`확인`이 아니라 `송장 저장`)
- 화면당 강조 버튼(primary)은 하나만
- 크기와 위치는 피츠의 법칙을 따름

### 2. 입력 필드와 폼(Input Fields & Forms)
결제·가입·리드 확보가 일어나는 지점이라 사용성이 곧 매출로 연결됨

- 필수가 아닌 필드는 과감히 제거
- 레이블은 필드 밖에 항상 보이도록 유지 (placeholder로 대체 금지)
- 입력 형식을 유연하게 허용 (하이픈·공백 등 자동 처리)
- 오류 메시지는 해당 필드 옆에 표시하고 기존 입력값은 보존

> **Expedia 사례**: 결제 폼에서 선택 항목이던 `Company` 필드 하나를 제거해 연간 1,200만 달러의 추가 매출을 얻음. 사용자가 해당 필드를 은행명·주소로 오해해 입력하면서 결제 검증이 실패하고 있었음

### 3. 메뉴(Menu)
필요할 때 나타나는 명령·탐색 목록. 공간을 절약하면서 사용자가 명령을 기억하는 대신 보이는 선택지를 인지하게 함

- 사용자 어휘를 사용하고 카드 소팅으로 검증
- hover가 아닌 click으로 열기
- 계층은 최대 2단계까지만
- 데스크톱은 내비게이션을 노출, 햄버거 메뉴는 모바일 한정

### 4. 링크(Link)
클릭하면 다른 위치로 이동하는 텍스트 또는 이미지. 웹의 기본 단위

- 파란색 + 밑줄 관례 유지
- 앞쪽 11자에 핵심 정보 배치
- 링크가 아닌 요소에 링크 서식을 쓰지 않음
- 링크가 많은 화면에서는 방문/미방문 상태를 구분

### 5. 대화상자(Dialog)
질문·결정·확인이 필요할 때 주 작업 흐름을 중단하는 보조 창

- 정말 흐름을 막아야 하는 결정에만 모달 사용
- `확인/취소` 대신 결과를 나타내는 레이블 사용
- 안전한 선택을 기본값으로 두고 `Esc`는 항상 취소로 동작
- 되돌릴 수 있는 작업이면 확인창보다 실행 취소(undo)를 제공

### 6. 알림과 오류 메시지(Alerts & Error Messages)
어떤 일이 발생했거나, 진행 중이거나, 실패했음을 전달

- 무엇이 왜 실패했는지 평이한 언어로 설명
- 발생 위치와 복구 방법을 함께 제시
- 아이콘 + 색상 + 텍스트를 중복 사용 (색각 이상 대응)
- 알림 남발 금지

### 7. 아이콘(Icon)
객체·행동·상태를 나타내는 작은 그림. 공간을 절약하고 번역 없이 사용 가능

- 공간이 정말 부족한 경우가 아니면 텍스트 레이블과 함께 사용
- 이미 존재하는 표준 메타포를 사용
- 배포 전 5명에게 인식 테스트
- 파비콘은 16×16 픽셀에서 판독 가능해야 함

### 8. 체크박스 · 라디오 버튼 · 토글
독립 선택은 체크박스, 상호 배타적 선택은 라디오 버튼, 즉시 적용되는 설정은 토글

- 사각형은 독립 선택, 원형은 배타 선택
- 세로로 나열하고 레이블도 클릭 가능하게 처리
- 라디오 그룹은 합리적인 기본값을 미리 선택
- 토글은 변경이 즉시 반영될 때만 사용

### 9. 탭(Tab)
한 화면 영역을 여러 병렬 패널이 공유하고 한 번에 하나만 보여주는 구조

- 한 줄을 넘기지 않음 (여러 줄은 공간 기억을 파괴함)
- 레이블은 1~2 단어
- 선택된 탭과 아래 패널을 시각적으로 연결
- 가능하면 탭마다 고유 URL 부여

### 10. 검색(Search)
텍스트 필드와 돋보기 아이콘을 결합해, 사용자가 내비게이션 구조 대신 자기 말로 목표를 입력하게 함

- 아이콘으로 숨기지 말고 페이지 상단에 입력창을 열어둠
- 입력창 너비는 최소 27자
- 돋보기 아이콘 + `Enter` 키 관례 준수
- 검색 로그를 매달 분석해 사용성 문제를 발굴

## AI 인터페이스에서의 시사점
생성형 인터페이스가 늘어날수록 컨트롤은 오히려 더 불변해야 함

- 화면 구성이 예측 불가능해질수록, 익숙한 위젯이 방향 감각과 인지적 안정성을 제공
- 사용자 승인·실행 취소가 필요한 에이전트 시스템에서 관례는 감독 수단으로 작동

## 정리
- 익숙한 컨트롤은 작업 속으로 사라짐. 인터페이스 요소에 대한 최고의 칭찬은 **보이지 않는 것**
- 이 요소들이 오래 살아남은 이유는 유행이 아니라 인간의 상수에 대응하기 때문
- 결국 **관례 자체가 디자이너의 가장 강력한 도구**
