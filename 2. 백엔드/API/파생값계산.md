## 화면은 프론트, 저장은 서버
- 칸을 고치면 합계가 바로 바뀌어야 하므로 **화면 표시용 계산은 프론트의 미리보기**로 둔다
- **저장되는 값의 정본은 서버가 계산한다.** 클라이언트가 보낸 계산값은 받지 않거나 무시한다
- OWASP : 금액이나 상태에 영향을 주는 값은 서버에서 다시 계산한다. 클라이언트 상태는 입력일 뿐 정답이 아니다

  > Always re-derive security-relevant values (prices, permissions, ownership) on the server. Client state is input, not truth.

- OWASP : 가격, 소계, 세금, 합계는 클라이언트에게서 받지 않는다. 식별자와 수량만 받고 나머지는 서버가 계산한다

  > Never accept a price, subtotal, tax, or total from the client. Accept product identifiers and quantities only, and compute the rest on the server from your own database.

- 계산 필드는 API 계약에서 읽기 전용으로 두어 PUT이나 PATCH 본문에 다시 싣지 않게 한다

## 렌더링 성능은 근거가 약하다
- "저사양 PC에서 렌더링 이슈"는 합계를 서버로 옮길 근거가 되지 못한다. 행 12개에서 숫자 몇 개를 더하는 계산이다
- AG Grid : value getter는 값이 필요할 때마다 실행되지만, 대부분은 빨라서 체감 성능 영향이 없다

  > For most use cases, this will not be an issue, as Value Getters will execute quickly and not have any noticeable performance implications for your application.

- 성능 문제가 없으면 Value Cache도 필요 없다

  > If you are not using Value Getters, or you don't have performance problems, then you do not need the Value Cache.

- 리뷰에서 약한 근거를 섞으면 반박당하기 쉽고, 강한 근거(정본 문제)까지 약해 보인다
